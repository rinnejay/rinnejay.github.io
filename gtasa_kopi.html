GTA SA Kopi

1.54 Studi Kasus Stable

Studi kasus nyata: menjalankan dunia terbuka GTA: San Andreas (grove/Los Santos) di atas engine Kopi — mulai dari format aset KCM, streaming dunia, renderer 3D, sampai APK Android yang benar-benar bisa jalan.

Kenapa KCM?

Format lama .kpak menyimpan teks OBJ/MTL dan PNG terkompresi. Runtime harus mem-parse teks dan men-dekode zlib setiap model di-stream — lambat dan rawan stall. KCM (Kopi Compiled Model) menyimpan hasil yang sudah siap GPU: geometri terkuantisasi, material sebagai byte warna, dan tekstur RGBA8 mentah.

Format KCM v1

BagianUkuranIsi
Header64 Bmagic KCM1, versi, flags (bit0 = UV, bit1 = sudah Y-up), jumlah part/material/tekstur, skala kuantisasi, offset section
Part32 Bnama, rentang vertex/indeks, indeks material
Material32 Bwarna Kd/Ka/Ks/alpha, shininess, illum, indeks tekstur
Tekstur16 B + pikselnama, lebar/tinggi, offset data RGBA8
Vertex10 B/vertexint16 x,y,z,u,v
Indeks4 B/indeksuint32, segitiga

Packer membakar konversi Z-up (GTA) ke Y-up (engine): (x,y,z) -> (x,z,-y), UV v -> 1-v, dan winding (a,b,c) -> (a,c,b). File lama tanpa flag bit1 tetap dibaca dengan konversi di runtime.

Dua mode aset

Packer punya dua keluaran. Bytecode dan kode Java sama persis untuk keduanya; runtime memilih berdasarkan field parts di manifest.

1. Multi — satu KCM berisi satu model penuh

# tiap model -> satu file <model>.kcm (banyak part di dalamnya)
python3 tools/pack_kcm.py --obj ganghous01_lax \
    --objdir build/obj --texdir assets/tex --out build/kcm_multi

Manifest tidak punya field parts; runtime memuat kcm/<model>.kcm.

2. Single — satu KCM berisi satu part/objek

# tiap grup usemtl -> file sendiri <model>_p<i>.kcm
python3 tools/pack_kcm.py --obj ganghous01_lax \
    --objdir build/obj --texdir assets/tex --out build/kcm_single --split

Manifest diberi "parts": N per model; runtime memuat <model>_p0.kcm … _p(N-1).kcm lalu menggabungkannya. Hasil pada proyek ini: 68 file, 21 MB (multi: 9 file, 20 MB).

Menggabungkan part di runtime

// KcmModel.kop
static void merge(ObjModel dst, ObjModel src) {
    ObjPart p = src.head.next;
    while (p != src.head) {
        ObjPart pn = p.next;
        p.next = dst.head;
        dst.tail.next = p;
        dst.tail = p;
        dst.partCount = dst.partCount + 1;
        p = pn;
    }
    dst.totalVertices = dst.totalVertices + src.totalVertices;
    dst.totalFaces = dst.totalFaces + src.totalFaces;
    dst.recomputeBounds();
}

Tidak perlu offset indeks: setiap part punya Mesh sendiri, jadi cukup menyambung linked list. Bila salah satu file part hilang, loader otomatis jatuh ke <model>.kcm (mode multi), sehingga satu game.kbc tetap kompatibel dengan kedua layout aset.

Streaming dunia

KpakStream mengubah manifest menjadi tabel datar sekali saat load, lalu tiap frame:

  1. membuang instance yang lebih jauh dari unloadRadius (96 m);
  2. memasang maksimal 8 instance dari model yang sudah siap;
  3. memuat paling banyak satu model baru per frame (hindari stall);
  4. menandai model gagal secara permanen agar tidak dicoba berulang.

Collider memakai sisi terpendek bbox (bukan diagonal), sehingga radius rumah tidak menutup jalan. Pohon memakai radius 0,55 m.

Perbaikan renderer

  • Normal menghadap kamera — Renderer3D.setTwoSided() (opt-in, default 0) membalik normal face bila menghadap menjauh. Jalan tidak lagi hitam, tanpa mengubah perilaku renderer lama.
  • Batch terakhir ter-flush — GlesSubmit.present() memanggil flush() sebelum Net.glPresent(); sebelumnya objek terakhir tiap frame hilang.
  • Tekstur case-insensitive — MTL GTA menulis craproad5_LAe.png sementara file bernama craproad5_lae.png. Lookup di packer dan generator kini case-insensitive; permukaan abu-abu datar hilang.
  • Kamera — pitch diperbaiki, kaki pemain di py = 0 (digambar py + 0.35).

Gameplay

  • Maju mengikuti arah pandang kamera (+z saat yaw 0); strafe dan setir mobil tidak terbalik.
  • Hadap karakter pyaw = atan2(worldX, worldZ).
  • Mobil terparkir 6 m di belakang spawn; masuk/keluar dari sisi mobil, cooldown 30 frame.

Android: layar hitam & JNI

Penyebab layar hitam yang sulit terlihat: libkopivm.so mengekspor simbol JNI untuk paket com.rinnejay.kopiide.AndroidKopiVM, sedangkan kelas game ada di com.gtasa_kopu. Setiap panggilan native pertama melempar UnsatisfiedLinkError — proses mati sebelum sempat menulis log.

$ nm -D libkopivm.so | grep Java_
Java_com_rinnejay_kopiide_AndroidKopiVM_nativeInit
Java_com_rinnejay_kopiide_AndroidKopiVM_nativeLoad
...

Solusi: kelas AndroidKopiVM dipindah ke paket com.rinnejay.kopiide (nama paket Java bebas dari applicationId). MainActivity tetap com.gtasa_kopu.MainActivity dan hanya meng-import kelas tersebut.

Log yang bisa dibaca

/storage/emulated/0/Android/media/<package>/gtasa_kopu_log.txt   # Java + stdout VM
/storage/emulated/0/Android/media/com.gtasa_kopu/gtasa_kopu_vm.txt  # Log.toFile dari Kopi
logcat -d | grep GTASA_KOPU

Semua log Java juga dikirim ke logcat dengan tag GTASA_KOPU, jadi tetap terbaca walau penulisan file diblokir scoped storage.

Build APK

cd ~/gtasa_kopi
sh tools/build_apk.sh both      # atau: multi | single
ModePaketAset KCMFile

Paket berbeda agar kedua varian bisa terpasang berdampingan. Script juga mengompilasi bytecode dari src/, memakai ulang android.jar dari cache (~/.cache/gtasa_kopi/), dan menyalin hasil ke /storage/emulated/0/Download/.

Aset mati tidak ikut terpaket

Dulu kpak/ (2,9 MB) dan world_50x50.kpak (37 MB) ikut masuk APK padahal tidak pernah dirujuk. Setelah dibersihkan: 16 MB → 5,3 MB. Cek cepat:

grep -ao "assets/[A-Za-z0-9_./-]*" game.kbc | sort -u
# assets/grove.json
# assets/kcm/
# assets/tex/desgreengrass.png
# assets/world_manifest.json

Verifikasi

  • Simulasi 60 frame: 9 model termuat, 1121 instance, 836 collider, jalan bertekstur.
  • Simulasi "gaya APK" (tanpa prefix assets/) memuat manifest + KCM dari kcm/.
  • Frame 20 mode multi dan single menghasilkan PPM identik (MD5 a44877d2…) — pemecahan part tidak mengubah visual.
  • game.kbc di kedua APK identik; 9 KCM (multi) / 68 KCM (single); tidak ada kpak.

Catatan

  • libkopivm.so saat ini hanya tersedia untuk arm64-v8a; APK tidak akan jalan di perangkat 32-bit.
  • Simulasi desktop memakai KOPISIM=1 MAXFRAME=N kopivm game.kbc, snapshot build/sim*.ppm.
  • Radius streaming 72 m (load) / 96 m (unload) — naikkan bila ingin draw distance lebih jauh, dengan biaya memori tekstur.
